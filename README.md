# Sunrise Industries 勤怠管理システム

## 想定シナリオ（クライアント）

株式会社サンライズ工業（従業員150名規模の製造業）は、これまで紙とExcelで
出退勤管理・有給申請を行っており、集計ミスや申請の紛失が課題になっていた。
本システムはその課題を解決するための社内向けWebシステムという想定で設計した。

## 使用技術（すべてJava）

フレームワークに頼らず、Java標準API + Servlet API の組み合わせだけで
実装している。使っている技術を自分の言葉で説明できることを優先した。

| 領域 | 技術 |
|---|---|
| 言語 | Java 17 |
| Webサーバー | Jetty（組み込み・Tomcat等の別途インストール不要） |
| Web層 | Servlet API（jakarta.servlet） |
| DB | H2 Database（組み込み・ファイル永続化） |
| DBアクセス | JDBC（生SQL、ORMなし） |
| ビルド | Maven |

ビューはJSPやテンプレートエンジンを使わず、Java 17のテキストブロック
（`"""..."""`）でHTMLを組み立てている。DIコンテナも使わず、Servlet同士は
コンストラクタでDAOを直接生成するシンプルな構成。

## 機能一覧

- ログイン／ログアウト（社員コード＋パスワード、SHA-256＋ソルトでハッシュ化）
- 社員：出勤・退勤の打刻、当月の勤怠一覧、残業時間の自動集計
- 社員：有給申請（開始日・終了日・理由）
- 管理者：チームの本日の勤怠状況ダッシュボード
- 管理者：有給申請の承認／却下
- 管理者：当月の全社員勤怠をCSV出力
- ロールベースのアクセス制御（`AuthFilter`で未ログイン・権限外アクセスを制御）

## ディレクトリ構成

```
src/main/java/com/sunrise/attendance/
├── Main.java          サーバー起動・ルーティング定義
├── model/              Employee, AttendanceRecord, LeaveRequest など
├── dao/                JDBCによるデータアクセス層
├── servlet/            画面表示・フォーム処理
├── filter/             認証・認可フィルター
└── util/               パスワードハッシュ化、HTML共通レイアウト
```

## 起動方法

```
mvn clean package
java -jar target/attendance-system.jar
```

ブラウザで `http://localhost:8080/` を開く。

### デモ用アカウント

| 役割 | 社員コード | パスワード |
|---|---|---|
| 管理者 | admin001 | admin123 |
| 社員 | emp001 / emp002 / emp003 | password123 |

初回起動時にデモ用の社員・勤怠実績・有給申請データが自動投入される
（`data/`フォルダにH2のDBファイルが作成される）。

## 設計上のポイント（面接で聞かれそうなこと）

- **なぜフレームワークを使わなかったか**：Spring Bootなどの学習コストを
  かける前に、Servlet/JDBCというJava Webの基礎部分を自分で組み立てて
  理解を深めるため。仕組みを理解した上で今後Spring Boot等へステップ
  アップする前提。
- **なぜ組み込みJetty＋H2にしたか**：Tomcatや外部DBサーバーの個別
  インストールなしに `java -jar` 一発で誰でも動かせるようにするため
  （面接官がその場で動作確認しやすいことを優先）。
- **残業時間の算出ロジック**：`AttendanceRecord#getOvertimeMinutes()`で
  1日8時間を超えた分を残業として計算。休憩時間控除は未実装（実運用では
  必要になる想定）。
- **パスワード保護**：ユーザーごとにランダムなソルトを付与しSHA-256で
  ハッシュ化。本番運用ではストレッチング付きのBCrypt等に置き換えるべき
  という認識あり（`PasswordUtil`にコメント記載）。
