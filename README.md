# ConWork 勤怠管理システム

## 作った理由

夏に参加した2Dayの仕事体験で、架空の企業の課題を見つけて要件定義をする、という上流工程の仕事を体験しました。そのとき、「ここで考えた要件を、実際にシステムとして自分で形にしたらどうなるんだろう」と思ったのがこれを作ったきっかけです。

テーマは勤怠管理にしました。労働基準法上、会社は社員の労働時間を客観的に把握する義務があるので、この業務自体はどこの会社にもあります。それでも紙やExcelで管理している会社がまだ多く、認証・権限分け・承認フロー・集計処理といった業務システムに必要な要素が一通り詰まっているテーマだと思ったので選びました。

## 想定シナリオ

特定の1社に絞るのではなく、**従業員100〜200人規模くらいの企業全般**を想定してシナリオと設計を考えました。この規模だと、KING OF TIMEのような多機能な勤怠SaaSは機能過多・コスト過多になりがちな一方、紙やExcelでの管理はまだミスや紛失のリスクが残ります。その間を埋める「必要十分な機能に絞った勤怠管理システム」として`ConWork`を位置づけています。

## 使用技術

Spring Bootのようなフレームワークを最初から使うこともできましたが、あえてJava標準API＋Servlet APIだけで組んでいます。フレームワークに頼る前に、Webアプリが裏側でどう動いているのかを自分の手で組み立てて理解しておきたかったからです。

| 領域 | 技術 |
|---|---|
| 言語 | Java 17 |
| Webサーバー | Jetty（組み込み・Tomcat等の別途インストール不要） |
| Web層 | Servlet API（jakarta.servlet） |
| DB | H2 Database（組み込み・ファイル永続化） |
| DBアクセス | JDBC（生SQL、ORMなし） |
| ビルド | Maven |

画面もJSPやテンプレートエンジンを使わず、Java 17のテキストブロック（`"""..."""`）でHTMLを組み立てています。DIコンテナも使わず、Servlet同士はコンストラクタでDAOを直接生成するだけのシンプルな構成にしています。

## 機能一覧

- ログイン／ログアウト（社員コード＋パスワード、SHA-256＋ソルトでハッシュ化）
- 社員：出勤・退勤の打刻、当月の勤怠一覧、残業時間の自動集計
- 社員：有給申請（開始日・終了日・理由、残日数不足時は申請をブロック）
- 社員：有給残日数の確認（毎年4/1一斉付与、繰越なし）
- 管理者：チームの本日の勤怠状況ダッシュボード
- 管理者：有給申請の承認／却下（申請者の有給残日数を確認しながら判断可能）
- 管理者：当月の全社員勤怠をCSV出力
- 管理者：給与計算用の月次サマリーCSV出力（実労働時間・残業時間・欠勤日数・有給消化日数）
- ロールベースのアクセス制御（`AuthFilter`で未ログイン・権限外アクセスを制御）

## ディレクトリ構成

```
src/main/java/com/conwork/attendance/
├── Main.java          サーバー起動・ルーティング定義
├── model/              Employee, AttendanceRecord, LeaveRequest など
├── dao/                JDBCによるデータアクセス層
├── servlet/            画面表示・フォーム処理
├── filter/             認証・認可フィルター
└── util/               パスワードハッシュ化、HTML共通レイアウト
```

## 起動方法

```
mvn clean package
java -jar target/attendance-system.jar
```

ブラウザで `http://localhost:8080/` を開く。

## 設計で意識したこと（聞かれたら答えられるようにしているメモ）

- **なぜフレームワークを使わなかったか**：Servlet/JDBCというJava Webの基礎部分を自分で組み立てて理解を深めたかったから。仕組みを理解した上で、今後Spring Bootなどにステップアップするつもり。
- **なぜ組み込みJetty＋H2にしたか**：Tomcatや外部DBサーバーを個別にインストールしなくても、`java -jar`一発で動かせるようにしたかったから。
- **残業時間の算出ロジック**：`AttendanceRecord#getOvertimeMinutes()`で1日8時間を超えた分を残業として計算している。休憩時間の控除は未実装（実運用では必要になると思う）。
- **パスワード保護**：社員ごとにランダムなソルトを付与してSHA-256でハッシュ化している。本番運用ではストレッチングありのBCrypt等に置き換えるべきだと分かった上で、今回はここまでにした（`PasswordUtil`にもコメントで書いている）。
