# 追加機能2 要件定義（実装済み）

管理者の日々の運用を助けるための5機能。想定ターゲット（専任の労務担当がいるとは限らない
100〜200人規模の企業）を意識し、複雑な設定を増やさずに実装できる範囲に絞っている。

## 1. 36協定アラート

### 目的
残業時間が労働基準法の上限に近づいている社員に、管理者が気づけるようにする。

### 仕様
| 項目 | 仕様 |
|---|---|
| 判定基準 | 当月の残業時間が45時間以上で「注意」、80時間以上で「危険」のバッジを表示 |
| 表示場所 | 管理者ダッシュボードの「本日のチーム勤怠状況」テーブル、および同ダッシュボードのアラート件数サマリー |
| 実装 | `DashboardServlet#overtimeBadge()`。既存の`AttendanceDao#findForMonth`を使った単純な月合計 |

### スコープ外
- 複数月平均（2〜6ヶ月平均80時間以内）の判定
- 特別条項（年6回までの例外的な上限緩和）の考慮
- 休日労働時間の別枠管理

単月の残業時間のみで簡略化しており、実際の36協定の運用には他の考慮事項がある旨をREADMEに明記している。

## 2. 打刻漏れの検知

### 目的
「休みなのか、打刻を忘れているだけなのか」を管理者が見分けられるようにする。

### 仕様
- 当日の出勤打刻がなく、かつ現在時刻が10:00を過ぎている場合、「打刻漏れ？」のバッジを表示する
- 10:00という基準時刻は固定値（会社ごとの始業時刻設定などは対象外）

### スコープ外
- 会社ごとの始業時刻のカスタマイズ設定
- 打刻漏れの事後修正フロー（別途「今後やりたいこと」として整理済み）

## 3. 部署別の絞り込み

### 仕様
- 管理者ダッシュボードと勤怠一覧画面に部署のプルダウンを追加し、選択した部署の社員のみに絞り込む
- 部署一覧は`employees`テーブルから動的に取得（`EmployeeDao#findAllDepartments`）

## 4. チームの今後の有給予定一覧

### 目的
少人数チームで有給取得が重なることによる業務への影響を、事前に把握できるようにする。

### 仕様
- 承認済みで開始日が本日以降の有給申請を、全社員分まとめて日付順に表示（管理者ダッシュボード）
- カレンダーのような視覚的な表示ではなく、シンプルな一覧表示に留めている

## 5. 過去月の勤怠一覧閲覧

### 仕様
- `/attendance?month=yyyy-MM`で任意の月を指定可能。省略時は当月
- 前月・翌月への移動リンクを表示（当月より先（未来）には移動できないようクランプ）
- 社員・管理者どちらの画面にも対応
