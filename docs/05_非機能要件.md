# 非機能要件一覧

IPA「非機能要求グレード」の分類（可用性・性能/拡張性・運用/保守性・移行性・セキュリティ・環境/エコロジー）を参考に、
現行実装の対応状況と今後の対応方針を整理する。SIer各社の提案書・設計書でよく使われる分類軸に合わせている。

| 分類 | 項目 | 現状の対応状況 | 今後の対応方針 |
|---|---|---|---|
| 可用性 | 稼働時間 | 想定なし（デモ用単一プロセス起動） | 社内イントラ想定のため平日日中稼働を想定。冗長化は対象外と明記 |
| 可用性 | 障害時のデータ保全 | H2はファイル永続化のみ、バックアップ機構なし | 定期バックアップ（ファイルコピー）方針を明記 |
| 性能・拡張性 | 同時アクセス | 想定従業員150名規模、Jetty組み込みで検証未実施 | 負荷試験（JMeter等）の実施、コネクションプール導入 |
| 性能・拡張性 | データ量増加 | 月次データが蓄積し続ける設計（アーカイブなし） | 過去データのアーカイブ方針、月次ページングの実装（README拡張候補） |
| 運用・保守性 | ログ | `System.out.println`のみ、レベル分けなし | SLF4J+Logbackへの置き換え、ログレベル・ログローテーション設計 |
| 運用・保守性 | 監視 | なし | ヘルスチェックエンドポイント、稼働監視の設計 |
| 運用・保守性 | エラーハンドリング | Servlet標準のエラーページ（`sendError`）のみ | 共通エラーページ、例外ハンドリングの統一 |
| 運用・保守性 | テスト | 自動テストなし | JUnit5によるDAO層・ドメインロジック（残業計算等）のユニットテスト整備 |
| 移行性 | 環境構築 | `java -jar`一発起動、外部ミドルウェア不要（組み込みJetty+H2） | Docker化でOS依存を排除、CI/CDパイプライン整備 |
| セキュリティ | 認証 | 社員コード＋パスワード、セッションベース | 多要素認証は対象外（社内システム想定のため） |
| セキュリティ | パスワード保護 | SHA-256＋ソルト（`PasswordUtil`にBCrypt化の課題認識を記載済み） | BCrypt等のストレッチングありハッシュへの置き換え |
| セキュリティ | 認可 | `AuthFilter`によるロールベースアクセス制御（管理者専用パスの403制御） | 部署別・複数管理者の承認権限（README拡張候補） |
| セキュリティ | 通信 | HTTP（デモ環境のため） | 本番運用ではリバースプロキシ配下でTLS終端 |
| セキュリティ | 入力対策 | SQLインジェクション対策（PreparedStatement中心）、XSS対策（`Layout.escape`によるHTMLエスケープ） | CSRFトークンの導入（現状フォームに未実装） |
| セキュリティ | セッション管理 | Servlet標準セッション、ログアウトで破棄 | セッションタイムアウト値の明示、セッション固定攻撃対策の確認 |
| 環境・エコロジー | リソース消費 | 組み込みJetty+H2で最小構成 | 特記事項なし |

## 面接・提案の場で語れるポイント

- 「非機能要件は何も考えていない」ではなく、**現状どこまでで、何を意図的に対象外にしたか**を説明できることが、
  SIerの実務（要件定義〜提案）に近い視点として評価されやすい。
- 特に「セキュリティ」行は、`PasswordUtil`のコメントや`AuthFilter`の実装と紐づけて、
  コードと設計書の記述が一致していることを示せると説得力が増す。
