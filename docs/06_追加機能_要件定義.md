# 追加機能 要件定義（検討中・実装予定）

現行システムに対する拡張案として、以下2機能の要件定義を行った。想定ターゲット（紙・Excel運用からの
乗り換えを検討する中小規模事業者、複雑な就業規則を持たない企業）に合わせ、あえて機能をシンプルに
絞っている。

## 1. 有給休暇の残日数管理

### 目的
社員が自分の有給残日数を把握した上で申請できるようにする。管理者も承認時に残日数を確認できるようにする。

### 仕様

| 項目 | 仕様 | 備考 |
|---|---|---|
| 付与方式 | 基準日一斉付与（毎年4/1、全社員一律） | 労基法上は入社日基準が原則だが、就業規則がシンプルな中小企業向けという想定に合わせ、運用のしやすさを優先して基準日方式に統一 |
| 付与日数 | 勤続年数に応じた法定付与日数テーブルに基づく | 労働基準法の法定付与日数（6ヶ月:10日、1.5年:11日 … 6.5年以上:20日）を採用 |
| 繰越 | なし（当年度付与分のみを管理し、翌年度への繰越は行わない） | 労基法上は最大2年繰越可能だが、管理の複雑化を避けるため対象外とする |
| 消化 | 承認された有給申請の日数分を残日数から差し引く | 却下された申請は残日数に影響しない |
| 申請時チェック | 残日数が申請日数に満たない場合、申請自体をエラーとして受け付けない | 「警告のみで申請は通す」ではなく、ブロックする方針とした |
| 表示 | 社員ダッシュボードに「付与日数／残日数」を表示 | 管理者は承認画面で申請者の残日数を確認できるようにする |

### スコープ外（あえて対象外とした範囲）
- 比例付与（パート・週所定労働日数が少ない社員向けの按分計算）
- 時間単位・半日単位の有給取得
- 入社日基準での個別付与

## 2. 給与計算システム連携（CSV出力の拡張）

### 目的
勤怠データを、外部の給与計算ソフトや税理士・社労士への引き渡しにそのまま使える形で提供する。

### 想定利用者
管理者（実際の企業では総務・経理担当、または外部の税理士・社労士が給与計算を行うことが多いが、
本システムではその窓口を管理者ロールが担う想定）。

### 仕様

| 項目 | 仕様 | 備考 |
|---|---|---|
| 連携方式 | CSVダウンロードのみ | 外部システムとの自動API連携は行わない |
| 構造 | 既存の勤怠CSV出力を拡張する形とし、新しい画面・複雑な集計ロジックは追加しない | シンプルさを優先 |
| 出力項目 | 社員コード、氏名、実労働時間、残業時間、欠勤日数、有給消化日数 | 深夜労働時間・休日出勤の区分などは対象外 |
| 出力単位 | 社員1人1行の月次サマリー | 日次明細ではなく、給与計算にそのまま使える集計済みの形にする |

### スコープ外（あえて対象外とした範囲）
- 外部給与計算ソフト（freee人事労務、弥生給与など）とのAPI直接連携
- 深夜労働・休日労働の割増区分ごとの内訳
- 賞与・各種手当の計算

## 実装ステータス

両機能とも実装済み。

- 有給残日数管理：`LeaveBalanceCalculator`（付与日数の算出）、`LeaveRequestDao#sumApprovedDaysSince`（消化日数の算出）。ダッシュボード・有給申請画面・承認画面に残日数を表示し、申請時は残日数不足であればブロックする。
- 給与計算連携CSV：`PayrollCsvExportServlet`（`/export/payroll-csv`、管理者専用）で、社員1人1行の月次サマリーCSVを出力する。
